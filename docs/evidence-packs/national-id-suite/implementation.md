# Bounded National ID implementation handoff

This documentation-only PR does not implement the proposed Facts, activate candidates, run
production imports or approve publication. Each later PR must name its catalog rows, claim IDs,
scenario IDs, evidence date and remaining unknowns. Complete prerequisites before implementation;
use the [editorial lifecycle](../../editorial-process.md), not direct database state assignment.
The retired prototype is not a target. Keep authored content in draft pending independent review.

Task names are family-scoped: P-Ixx and N-Ixx retain the original handoff numbers where applicable.
The only shared task is [I02](../catalog-compatibility.md), implemented once. A shared Fact likewise
has one compatible registry definition, not competing family-specific migrations.

## N-I05

### Close and encode one domestic ID documentary family

**Prerequisites:** Applicable D02/D03/D09 and G02/G03 research; shared I02 before catalog changes.
Passport provenance task P-I01 is **not** a prerequisite for an independent ID increment.
**Bound:** One family per PR: N01, N02 successor, N04, N05, N06, then N07. N03 remains blocked
until its impossible old-card requirement is resolved. N08/N09 are excluded from this increment.

For the selected family obtain competent current identity/proof alternatives, forms, attendance/
capture, submission/collection, fee state and channel scope. Separate official requirements,
preparation and alternatives; do not import consular proof menus domestically. First issuance
is not inferred from possession alone. Marriage-condition ambiguity is not applicant uncertainty.

Add only the required typed Facts/Questions and one draft importer/command, using one atomic
public entry, private build and final verification exactly once. Preserve current expiry and
calendar-month renewal-deadline derivations. New event-date derivations follow only in a separate
bounded task after current amended-law review. New supporting evidence uses successor lifecycle
records, not edits to old published provenance or silent baseline signature refreshes.

**Acceptance:** Appropriate SC29–SC44/71 and SC63–SC70; real positive/negative proof-alternative
cases, repeat-import/drift rejection, late-failure rollback, source completeness, lifecycle and
coexistence tests. No invented fee, early window, fine or online-completion promise. In particular,
N02's new old-card evidence must not silently rewrite the 2026-08-26 baseline.

## N-I06

### National ID multiple changes and replacement/change combinations

**Prerequisites:** Shared I02, G07 and applicable G02/G03/G08 closure.
**Bound:** N09 decision table and one evidenced combined subcase per PR, not passport P02/P06
work or a generic other-record-correction catch-all. N08 remains specialist scope.

Specify possession, expiry and change-kind combinations including UNKNOWN. Confirm one
transaction versus ordered transactions, accepted evidence and fee treatment. Do not discard
multiple, mark coherent changes contradictory, force unchanged renewal or charge for several
invented transactions. Preserve the existing none-plus-expiry invariant without broadening it
to lost-with-known-expiry.

**Acceptance:** Applicable SC35–SC39/42/59/67 plus positive/negative/UNKNOWN scenarios for each
newly supported combination; non-overlapping candidates, explicit inconclusive gaps and the
approved successor/catalog rollout for any changed baseline behavior.

## N-I07

### One verified ID mission/committee and family per PR

**Prerequisites:** Shared I02, applicable D04/D07/D09 and G06/G08/G09 resolution.
**Bound:** One mission and one ID family, not London/Dubai/Sydney in one importer. A passport
mission's evidence does not establish this mission's ID tariff or first-issuance service.

Verify territory, live committee/counter availability, transaction, proof alternatives,
approvals, currency/charge/payment, collection and dates. Separate first-ID committees from
ordinary renewal counters; do not invent replacement handling from an old-original renewal
checklist. Resolve age and fee discrepancies without calculating an assumed price increase.
Use compatible country/region Facts with evidenced rules, not user choice of legal competence.

**Acceptance:** SC47/55–SC58/60/61/68 and cross-mission/currency negatives; no stale committee
appointment, universal military rule, guaranteed timing or unverified lost/damaged-ID support.
Other overseas scopes remain explicitly unsupported.

## N-I08

### Publish only the reviewed National ID subset

**Prerequisites:** Exact included rows' research, implementation and review gates closed.
**Bound:** Coherent ID Procedure Versions via staff review/publication, independently of the
passport suite. No direct status assignment, automated self-approval or deployment in a code PR.

Assign accountable author, independent bilingual reviewer and applicable legal/military/
custody/contested-identity specialists. Verify candidate/version availability, consequential
Question coverage, negative/UNKNOWN behavior, current evidence and required Planning Scenarios.
Inspect actual Arabic/English plans and obtain independent approvals. Run relevant PostgreSQL
publication/importer/API tests and pure-planner tests plus CI production checks.

**Acceptance:** Applicable SC59–SC70, reviewed plans with local unknowns, preserved required
database histories/import seals and explicit unsupported boundaries. Update each catalog row
with its actual version/PR/gaps, not a blanket full-suite-complete label. Reassess old renewal
Markdown under the [independent retirement criteria](../README.md#when-the-old-markdown-can-leave-the-active-tree);
no need to wait for every passport family to finish.
